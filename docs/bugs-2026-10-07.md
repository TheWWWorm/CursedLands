## Persistence and compatibility

Scripted move, turn and animation orders survive saves alongside VM waits.
Ordinary player orders retain their previous load behavior. An interrupted
story animation restarts its clip after loading. Old recruiter/tunnel saves
with the exact known wait can recover the lost movement order.

Legacy camp recovery requires a unique completed choice and an untouched
default main-hero stat triple. Modified legacy heroes without a receipt are
left alone rather than guessing which training to preserve. New receipts can
complete partial grants without duplication.

Movie saves wait until the completion barrier releases. Loading cancels the
barrier; peer loss and a real-time watchdog prevent permanent modal locks.
Co-op protocol is **5**, because older clients cannot acknowledge this
handoff. All peers must use the new build together. Save additions are optional
and old saves still load.

No original assets, generated private caches or user saves are included.

## Reproducible focused tests

`tools/tests/camp_grants.gd`, `coop_story.gd`, `coop_movie.gd` and
`shop_spells.gd` run through the existing `--tool` entry point with the user's
own original game data. Story tests default to a fresh recruiter sequence;
`--scene=cz1h --save=/absolute/path/to/a/copied/save.sav` tests the tunnel
sequence. `--reload-around` saves during the scripted walk;
`--legacy-save` removes only the new story-order field from that isolated test
save. `--guest-at=301,61` reproduces the tunnel detour. `--single` provides a
single-player control. Movie tests model presentation completion explicitly.
