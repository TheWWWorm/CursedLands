# Project review — 2026-10-28

A whole-repository survey taken at `c166495c` (release 1.35.0): gameplay code
health, test infrastructure, repository hygiene, the native layer and build,
and UI, localization, tooling and the web build. The items are ranked by the
value of fixing them. Items marked *done* were fixed in the change that added
this document; the rest are open maintainer decisions. Figures are from the
survey date and are not updated afterwards.

## 1. Repository size: 1.74 GiB pack, 70% of it validation captures

- `docs/validation` is 1.5 GiB at HEAD (8,029 files, 1,224 PNGs up to
  5120×2880). PNG never delta-compresses, so it is 1.33 GiB of the pack. It
  grew 928 MiB in the week of 2026-10-20. Only 31% of the PNG basenames are
  referenced from any tracked Markdown, and 2,280 of those files contain
  absolute workstation paths.
- `public/index.pck` has been rewritten 63 times (664 MiB raw, 191 MiB
  packed); `public/wiki` has 38,753 historical blob versions with single
  commits touching up to 8,940 files, which makes `git log` and blame on the
  web build unusable.
- Native binaries in `game/src/native/bin`: 105 historical blobs, 227 MiB raw.
- Only 60 MiB of history lives outside HEAD's ancestry, so branch pruning or
  garbage collection would not help. GitHub reports the repository at 1.87 GB
  and every clone and every Cloudflare deploy pays for it.

Forward-only options, without a history rewrite: change the evidence policy
(validation captures to a separate evidence repository, release assets or Git
LFS, keeping only the Markdown summary and a few downscaled WebP images under
`docs/validation`); `git rm` the existing captures at HEAD (checkout 1.8 GiB
to about 0.4 GiB, clone size unchanged); deploy `public/` from an orphan
`deploy` branch or build it in the deploy step instead of committing it.
Reclaiming the 1.3 GiB already in history needs `git filter-repo` and
re-tagging 73 tags, which conflicts with the immutable-tag rule in
[versioning.md](versioning.md); that is a one-time owner decision.

## 2. The hosted web build cannot be regenerated from the repository

`public/service-worker.js` says it is generated by `tools/export_mobile.py`,
which does not exist. The web export preset and build script exist only as
per-release snapshots under `docs/validation/release-{1.28.0,1.31.0,1.31.1}/recipes/`
(the three `build.py` copies differ, and there are no recipes for 1.32 to
1.35), and `game/export_presets.cfg` has no Web or Android preset. Move the
export script and presets into `tools/` and `game/`, write `BUILD-INFO` from
them, and add a check that a rebuild from the tagged tree matches
`public/BUILD-INFO.json`.

## 3. A third of the Godot test corpus never runs

1,199 scripts live in `tools/tests`; 561 were registered in the focused
manifest or the gameplay catalog; 638 were registered in neither, of which
418 (39,730 lines) are referenced nowhere and 329 print a completion marker,
that is, they are real tests that silently rot. The rule that every fix
registers a regression test had no enforcement.

*Done:* a parse pass (`tools/check_test_scripts.py`) found 18 unregistered
scripts that no longer loaded; they are repaired, and the 20 native-versus-
script parity oracles that the README advertises are registered. Still open:
register what else still passes, delete the six byte-identical two-line stubs
(`arena_usability`, `arena_long_run`, `arena_pve` and their `*_ui` twins, all
equal to `arena_alliances`), allowlist helpers, and lint that every script is
registered, a base of a registered script, or allowlisted with a reason.

*Done (follow-up, 2026-10-28):* the rule is enforced.
`tools/check_issue_coverage.py` (CI and `tools/tests/test_issue_coverage.py`)
requires every issue the changelog links to appear in a registered case's
`issues` list or in `tools/issue_coverage_exceptions.json` with a reason; the
69 issues fixed before the registries recorded links are seeded there and an
entry must go when a test covers it. The reopened families each have a matrix
test now instead of one cell per report: `posture_transition_matrix` (every
one-shot × start posture × requested gait × offset, authority and replica;
#109/#113/#118) and `speed_scaling_matrix` (world time, Eagle Sight, mana and
walking at both speeds on load, after a fast save is reloaded and after travel;
#62/#98/#116/#119). The written-but-unregistered tests for #20/#38/#47/#89/
#105/#107/#108/#111 are registered (`pack_alert_recovery`, `ui_real_time`,
`memo_equivalence`, `pause_menu_ingame_frames`, `board_slide_frames`,
`esc_board_frames`, `board_render_latency`).

## 4. Two runners with diverging process control

80 focused cases duplicate catalog entries with the same script and
arguments. The focused runner is serial, waits the full timeout after a
`SCRIPT ERROR` (the catalog runner kills on the first diagnostic), has no
`--jobs`, and uses a different default resolution (1280×720 against
1280×800). Fold the focused manifest into the catalog with a `focused: true`
tag, or at least share `run_program`. Also, 133 of 843 registrations set
`min_checks` below half the script's static `check(` count (for example
`arena_item_first_click` 10 of 93), so a test that skips most of its body
still passes; record the last green count and lint
`min_checks >= 0.9 × last_green`.

*Done (follow-up, 2026-10-28):* both runners share
`tools/parity/process.py` (diagnostic patterns, summary parser, process-group
control that ends a test on the first diagnostic or at its timeout, the same
1280×800 window). The focused runner gained `--jobs`, the catalog's memory and
network gates, and for GPU Lab jobs follows the job's live `stdout.log` so a
diagnostic cancels the job and the complete log replaces the wrapper's 64 KiB
tail. `tools/raise_min_checks.py --apply` raises `min_checks` to 90% of a
green run's count and `test_registries.py` fails when the same registration
carries two thresholds. Folding the manifest into the catalog is still open.

## 5. The script-only platform configuration is never run

Windows refuses to start without the native DLL; Linux and Android fall back
silently; macOS and the browser always run the GDScript fallbacks of about 35
kernels. No runner launches the game with the `--ei-script-*` flags or without
`src/native/bin`, so the configuration shipped to macOS and browser players is
untested on desktop. Add a "no extension" lane (5 to 10 campaign and arena
cases run with the binaries removed) and measure its whole-game cost; that
number decides whether a macOS native build (feasible per CMake, needs
`CMAKE_OSX_ARCHITECTURES`, `macos` entries in the `.gdextension` files and
preset changes) is worth doing.

## 6. Native build provenance and leaked build paths

Seven of thirteen shipped binaries (`libmod_archive*`, `libmod_lua*`,
`libpath_nrd*`) embed an absolute workstation build path because their CMake
files apply `-ffile-prefix-map` only to the extension target, not to
`godot-cpp`, as `source/CMakeLists.txt` does. No manifest records which source
hash, godot-cpp commit and toolchain built each binary (only
`tools/build_path_nrd.py --check` does this, for NRD), and
`tools/check_release_assets.py` ignores native libraries. The 29 engine
patches have their order partly in prose and no apply-and-verify script. No
CMake target uses `-Wall`, hardening flags, sanitizers or a fuzz harness,
although the hand-written LZMA2 decoder, the vendored 7z SDK and Lua 5.1.5
consume downloaded installers and mod archives.

## 7. UI scale and input are reimplemented per screen

The project has one scene file; 127 UI scripts build every control in code.
The per-screen scale helper `_k()` exists in 11 files with 7 different
formulas, `font_px()` in 4 files with 3 bodies, and there are 74 literal
font-size overrides. Confirmed unscaled text: `wiki_panel.gd` lines 151, 157,
166 and 211 (13 px labels; the rescale block re-sizes 7 of 10),
`network_panel.gd` lines 165 and 173, and the 44×44 rune buttons at
`wiki_panel.gd:852`, all about a third of the intended size at 2160p. 22
files test `KEY_ESCAPE` directly instead of an InputMap action; `camp_view`,
`dialog_panel`, `wiki_panel`, `load_panel` and `mod_panel` have no gamepad
navigation hooks and `options_panel.pad_targets()` returns an empty list. A
shared `UiScale` helper (the SettingsDialog surface-scale-plus-oversampling
pattern already does this well) and a `cancel`/`confirm` action pair are the
fixes.

*Done (follow-up, 2026-10-28):* `game/src/ui/ui_scale.gd` holds the scale
rules (`fit`, `by_height`, `by_width`, `by_min_side`, `by_height_within`,
`font_px`, `dialog`, `reading`, …) and every screen's `_k()`/`font_px()` names
one of them; `game/src/ui/ui_input.gd` reads the `remake_cancel` /
`remake_confirm` InputMap actions declared in `project.godot`, and the 22
files compare through it. `tools/tests/test_ui_conventions.py` lints both.
The encyclopedia's secondary labels, toolbar buttons, sidebar search
controls, rune family tabs, rune pieces and the spell constructor's selector
follow the reading scale (`ui_scale_rules`, `ui_scale_high_res` with EN/RU/DE
captures at 720p/1440p/2160p; the first 2160p capture showed the toolbar and
selector still at 1×, which the review had not listed); the
`network_panel.gd` lines turned out to be
inside an OptionButton popup that already inherits the canvas scale. Gamepad
navigation hooks for the five panels remain open.

## 8. Gameplay code structure

Code quality is otherwise good: strong typing (17,689 typed against 186
untyped `var`), zero TODO/FIXME markers, no systemic copy-paste, validated
RPCs, explicit save migrations, no quadratic per-tick unit scans. The
structural debt is concentrated: `session.gd` (5,764 lines) dispatches 35
command and about 35 event types through flat string `match` and `if` chains
(`apply_command` 312 lines, `_on_event` 237); `script/vm.gd:_call` is one
716-line function with 145 string arms on the per-tick path; unit network
snapshots are positional arrays read with magic indices (`s[6] >> 19 & 15`,
`row[18]`) and the wire `PROTOCOL` number must be bumped by hand;
`nav_grid.gd` touches GameUnit `_occ_cell`, `_seq` and `_bucket` internals 68
times; command-line flags are re-parsed with `OS.get_cmdline_user_args()` at
105 sites including every unit constructor; archive reads return empty
buffers silently and only 7 of 22 callers check. Suggested order: a
`Features` object for flag and kernel detection (one day, low risk), named
snapshot fields with a round-trip regression, handler tables for `session.gd`
and `vm.gd`, then an occupancy API.

## 9. Smaller hygiene

- *Done:* no `.github/`, CONTRIBUTING or documentation index existed; a CI
  workflow, `CONTRIBUTING.md` and `docs/README.md` were added. Issue
  templates are still missing.
- `docs/` root has 130 loose files, about 98 of them dated validation
  artefacts, and 65 of 154 `docs/validation` topic folders have no README.
  Moving the dated files is a `git mv` pass with a link check.
- `*.import` is ignored globally; 6 are force-added and 273 textures
  re-import with defaults on every fresh clone. *Done:* 14 scripts lacked
  `.uid` files. One orphan `game/src/ui/arena_paving.gdshader.uid` remains.
- `public/wiki/images` holds 1,813 byte-identical duplicates (about 44 MiB)
  because image names are not content-addressed, and
  `public/wiki/BUILD-INFO.json` says 1.34.0 against the 1.35.0 release.
- Hard-coded workstation defaults in runnable code:
  `tools/parity/test_ext_perception_triggers.py:15`,
  `tools/tests/discord_ipc_probe.py:4`, `tools/tests/wiki_features.gd:15`,
  `tools/tests/worker_coop_delivery.gd:32`; 234 tracked files mention the
  private GPU Lab scheduler.
- Python: three contradictory minimum versions in the docs (3.9, 3.10 and
  3.11) while five scripts use `hashlib.file_digest` (3.11; *done:*
  `pyproject.toml` now states 3.11); seven copies of `digest()`; three
  independent RES-archive readers; `server_directory.py`, the only
  network-facing tool, has no tests and no POST rate limit.
- *Done:* 97 mod store, mod schema, session and main menu messages were
  English-only and 20 of them were string concatenations that could never be
  translated; they are RemakeText keys now and the translation check enforces
  this at the statement level for those files.
- The issue tracker shows the same reports recurring under new numbers
  (animation skip #109/#113/#118/#120, game speed #62/#98/#116/#119, corpse
  targeting #95/#103/#112, menu frames #89/#105/#111). That is the symptom of
  items 3 and 4: fixes land without a test that would catch the recurrence.
