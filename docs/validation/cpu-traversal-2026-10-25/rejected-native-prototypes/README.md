# Rejected native property-loop prototypes

Both prototypes use the qualified Linux runtime and the same current remake data, in isolated muted profiles. Their source, independent unmodified old methods, ABBA observations and build receipts are retained here. Neither prototype is in the game. These are synchronous screening measurements, not whole-game FPS claims or release qualifications.

Animation composition matched 7,937 exact state/transform checks but increased the measured 31-part composition block from 24.054 to 30.842 microseconds per frame (28.2%). Original composition at 0x50c230 has the same parent/child ordering already retained by the remake; this prototype did not change that behavior. No separate original Wine execution was needed to reject a slower internal implementation.

The unit-sound outer scan matched 201 limited state/stamp checks. Across 334 actors with 0, 16, 56 or 334 nearby actors, native execution was 31.4%, 40.5%, 48.1% and 50.7% slower. No sound behavior change is accepted: the probe intentionally stops before a full voice/footstep regression qualification. Near-actor animation and audio remained synchronous GDScript callbacks. Reading script properties and making callbacks was too expensive to justify this C++ loop. The exact before method and new prototype are available for review.

Both source edits, native registrations and Linux library changes were restored to b57eba96. Further work must use a different measured approach, rather than assuming a direct C++ translation helps. No Windows/Android build or original-game FPS comparison is claimed for these rejected prototypes.
