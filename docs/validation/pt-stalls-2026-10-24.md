# Vegetation preparation and staged texture uploads

Follow-up for local `1.28.0-experimental.6`, retaining the five-target changes
from [experimental.5](pt-five-targets-2026-10-24.md). No public release, tag or
push was made. Native Windows frame pacing remains unqualified.

## Measured causes and changes

A temporary diagnostic engine recorded shader source hashes and native pipeline
creation times. The late biome-cover color pipelines took 44–48 ms each; near
and far grass in Mirror water took 27–31 ms each. These shaders needed the
streamed cover's actual vertex layouts and the reflection viewport's MSAA/fog
variants, which the main-camera preparation had not covered.

Zone loading now prepares zero-area cover meshes through the real cover builder
and draws the warm-up materials through a small reflection view. That view uses
the production reflection framebuffer and environment settings and sees only
the warm-up geometry. It is released with the loading-time preparation owner.
Four stationary draws also prepare the ordinary color pass after Godot's
new-instance motion-vector state expires. A single draw only prepared the
moving variant of far grass.

Native resource timing also measured 9.77 ms uploading a whole replacement
texture array, within a 19.00 ms resource-creation step. Replacement scenes now
upload at most four layers, or approximately 1.5 ms of upload calls, per frame.
Each layer includes all its mips. The controller cannot publish the replacement
until uploads and acceleration structures finish; the old scene remains active.
Allocation and an individual driver call still have no hard real-time bound.

In the follow-up RTX 3090 Ti opening, resource creation measured 9.60 ms and
the largest texture-upload step 0.61 ms. Total upload work was 7.40 ms spread
across frames. The initial held-view maximum fell from 121.77 ms to 44.95 ms;
first-walk maxima were 28.58 ms before and 29.23 ms after. Both used the same
Godot cache seed and fresh private driver caches.

The follow-up opening also recorded one unexplained 160.03 ms downhill frame,
with no pipeline-counter change and only 1.38 ms in the traced-scene controller.
Other GPU Lab tests were compiling on the other GPU during that short run, so
shared CPU contention is a possible explanation, not an established cause.
The subsequent complete cold-cache traversal did not reproduce it. These
observations do not establish that every possible traversal hitch is removed.

After preparing both moving and stationary variants, the focused final engine
diagnostic measured **23.11 ms** in the held view, **26.95 ms** on the first walk
and **46.82 ms** downhill. The largest native pipeline creation remaining after
loading was **2.92 ms**, down from the late 27–48 ms color pipelines. This run
also did not reproduce the 160 ms outlier. See the
[final pipeline events](pt-stalls-2026-10-24/final-pipeline-events.json).

## Final production build

Candidate9, including preparation of the stationary pass, completed the full
route with the production engine on RTX 3090 Ti: **138 checks, zero failures,
124.53 metres, zero PT or responsive NRD inactive frames**. Ten region changes
retained history. The renderer used the same 4K/DLSS/FG settings as the cold
run below; this repeat used its Godot cache as a seed and a fresh private
driver cache. Other GPU tests were not running during the measured route.

| Initial held view | 15.50 ms | 18.88 ms |
| First walk out of ruins | 16.11 ms | 28.06 ms |
| Downhill path | 15.49 ms | 48.34 ms |
| Beach boar encounter | 16.25 ms | 55.06 ms |

The whole-route maximum was **57.81 ms**. Native NVIDIA FG was active on every
sampled unpaused frame and suspended while paused. The 60-rendered-FPS target
remained at scale 1.0. The unexplained earlier 160 ms frame was absent here as
well. Short CPU/resource and gameplay stalls remain; this is not a claim of
perfect frame pacing. See the [final production route](pt-stalls-2026-10-24/candidate9-final-route-recording-route.json)
and [its slow frames](pt-stalls-2026-10-24/candidate9-final-route-traversal-stalls.json).

## Complete cold-cache traversal

The production engine and candidate8 game code completed the recording-derived
route on RTX 3090, driver 580.178.04, through GE-Proton11-11. GPU Lab used a heavy
job with an isolated display and muted profile, free cursor and visible FPS.
No Godot shader/CPU cache seed was supplied. The route used the production
single-player simulation process and actual player movement, with live AI,
combat/looting, weather changes, pause/resume and a final look uphill.

Result: **138 checks, zero failures, 124.00 metres, zero PT or responsive NRD
inactive frames**. Twelve responsive region replacements retained history.
The 60-rendered-FPS target stayed at scale 1.0 because measured GPU time met
the target. Switching to progressive accumulation at the end correctly disables
that responsive-only budget and resets its statistics.

| Stage | Median rendered frame | Worst rendered frame |
| --- | ---: | ---: |
| Initial held view | 19.93 ms | 40.06 ms |
| First walk out of ruins | 20.60 ms | 32.77 ms |
| Downhill path | 19.80 ms | 46.60 ms |
| Beach boar encounter | 21.30 ms | 56.87 ms |
| Beach after combat | 20.31 ms | 60.91 ms |
| Shore after encounters | 19.34 ms | 43.06 ms |
| Look back uphill | 17.15 ms | 58.06 ms |

The maximum over all sampled stages was **60.91 ms**. Every sampled unpaused
frame had native NVIDIA FG active; SDK presents were approximately twice game
presents. FG suspended while paused and FSR FG remained unused. These counters
are not a native Windows pacing qualification. The CPU/GPU caches and device
differ from other runs, so these FPS values are not a matched throughput claim.

## Resource and history validation

- Staged-upload tests passed **14 checks on DX12 and 14 on Vulkan**. Readback
  matched all 19 array layers and six mip levels byte for byte. A partial scene
  could not render; cancellation and an injected upload failure released its
  CPU/GPU resources and left the live scene and NRD usable. GPU readback usage
  is added only by the test subclass, not by production allocation.
- Native NRD history transfer passed **12 checks on DX12 and 12 on Vulkan**
  after the upload change. Compatible surfaces retain the original denoiser
  and permanent textures; changed surfaces reject stale history independently.
- Mirror/RT-water preparation passed **68 checks**, including reflected-draw
  readiness, settings changes, camera recentering, fallback and cancellation.
  Its older fixture expected an immediate modal message; production already
  delays the message by 500 ms and omits finishing-only overlays. The corrected
  fixture advances only the test clock and starts the real water preparation
  owner before checking the delayed canvas. No production delay changed.
- Source import/export completed without script errors. No player-visible
  text changed; the existing EN/RU/DE controls and attribution are retained.
